# ساخت بک‌اند جنگو برای اتوماسیون مدیریت باشگاه

تصمیم‌های پایه (با گزینه‌های پیشنهادی، چون پاسخی ثبت نشد): **Django با قالب‌های سروری** (همین HTMLها به template جنگو تبدیل می‌شوند) + **SQLite** + **پیامک شبیه‌سازی‌شده** (ثبت در دیتابیس، بدون کلید API) + **ساخت در همین پوشه** به‌صورت in-place. تنها وابستگی خارجی خودِ Django است (بدون jdatetime/Pillow — تبدیل تاریخ شمسی و آپلود لوگو با کد خودمان).

## گام ۰ — بررسی محیط و راه‌اندازی
- چک `python`/`py`/`pip` و دسترسی به PyPI؛ ساخت venv در `.venv/` و نصب Django؛ `requirements.txt` و `.gitignore` (venv، db.sqlite3، `__pycache__`).

## گام ۱ — اسکلت پروژه
```
manage.py
gym_project/  (settings, urls, wsgi)  → LANGUAGE_CODE=fa, TIME_ZONE=Tehran, LOGIN_URL, templates/, static/
core/         (ابزار مشترک)
accounts/  members/  classes/  attendance/  payments/  notifications/  gyms/
templates/    (قالب‌های تبدیل‌شده — همان ساختار پوشه‌های فعلی)
static/css/style.css, static/js/main.js   (منتقل‌شده از css/ و js/)
```

## گام ۲ — اپ core (زیرساخت مشترک)
- `core/jalali.py`: تبدیل میلادی↔شمسی (پورت الگوریتم موجود در main.js، بدون وابستگی).
- templatetagهای `{% jdate %}` (نمایش شمسی)، `{% day_name %}` و تعیین آیتم فعال سایدبار.
- `JalaliDateField` سفارشی برای فرم‌ها (پارس «۱۴۰۲/۱۱/۰۱» با نرمال‌سازی ارقام فارسی).
- context processor: تنظیمات باشگاه در همه قالب‌ها + mixins نقش (مدیر/پذیرش).

## گام ۳ — مدل‌ها (بر اساس داده‌های واقعی قالب‌ها)
- **classes**: `Coach` (نام/تلفن)، `GymClass` (مربی، روزها، ساعت شروع/پایان، ظرفیت، وضعیت، توضیحات)، `ClassPlan` (جلسات ۱۲/۳۶/۱۲۰ + قیمت).
- **members**: `Member` (نام، موبایل، جنسیت، کلاس، مربی)، `Subscription` (عضو، کلاس، جلسات، مبلغ، شروع/پایان شمسی، جلسات باقی‌مانده، وضعیت محاسبه‌شده).
- **attendance**: `Attendance` (عضو، کلاس، تاریخ، وضعیت حاضر/غایب/موجه + یکتایی عضو-کلاس-تاریخ).
- **payments**: `Payment` (مبلغ، نوع پلن، روش، ثبت‌کننده، وضعیت، شماره پیگیری، یادداشت)، `Expense` (شرح، دسته، فروشنده، وضعیت، …).
- **notifications**: `SMSMessage` (نوع/متن/وضعیت/تاریخ)، تنظیمات سراسری پیامک، تنظیمات هر عضو (۴ سوییچ مطابق جدول)، `Announcement` (متن + کلاس‌های M2M → ثبت پیامک شبیه‌سازی).
- **gyms**: `GymSettings` تک‌نمونه‌ای (نام، تلفن، آدرس، توضیح، لوگو FileField، رنگ).
- **accounts**: پروفایل نقش (مدیر/پذیرش) + `GymSubscription` (اشتراک خود باشگاه در صفحه پروفایل).
- ثبت همه در admin + migrations.

## گام ۴ — فرم‌ها و ویوها
- ModelForm برای همه موجودیت‌ها + اعتبارسنجی سرور؛ فیلترهای جستجو/وضعیت/اشتراک/روز/دسته به‌صورت query param.
- CRUD کامل: اعضا، کلاس‌ها (+ویرایش پلن‌ها)، اشتراک‌ها، پرداخت‌ها (+ثبت دستی)، هزینه‌ها، اعلانیه‌ها، تنظیمات، کاربران پذیرش (ایجاد/ویرایش/فعال-غیرفعال/حذف)، تمدید اشتراک باشگاه.
- حضور و غیاب: انتخاب کلاس+تاریخ → ثبت گروهی وضعیت‌ها؛ تاریخچه با فیلتر عضو/بازه تاریخ.
- داشبورد و امور مالی: aggregation واقعی (درآمد/هزینه/سود/مطالبات، نمودار ۶ ماه، وضعیت دریافت‌ها، آخرین تراکنش‌ها).
- احراز هویت: LoginView با قالب login.html، لاگ‌اوت، LoginRequiredMixin روی همه صفحات پنل؛ نقش پذیرش به مالی/تنظیمات/حذف دسترسی ندارد.
- صفحه اول عمومی + فرم درخواست تماس؛ پیام‌های موفقیت/خطا با messages framework.

## گام ۵ — تبدیل قالب‌ها (جذب باقی اصلاحات ناتمام)
- `base.html` به قالب پایه واقعی با `{% block %}` — حذف کامل تکرار navbar/sidebar/footer از ۱۹ صفحه؛ نمایش toast پیام‌های جنگو.
- همه فرم‌ها `{% csrf_token %}`؛ صفحه‌بندی جنگو جایگزین JS؛ تاریخ‌ها با `{% jdate %}`.
- تکمیل اصلاحات نیمه‌کاره باقی‌مانده (notification/settings/profile/login/index) در همان متن تبدیل.
- `index.html`: جایگزینی تصویر placeholder مرده با SVG داخلی.
- ورود سمت کاربر: `main.js` لاغر می‌شود (حذف صفحه‌بندی/فیلتر سمت کلاینت که سرور انجام می‌دهد؛ نگه‌داشتن toast، همبرگر، رنگ ردیف حضور، پیش‌نمایش زنده تنظیمات).

## گام ۶ — داده نمونه و تست
- دستور مدیریتی `seed_demo`: مدیر (admin/admin123)، پذیرش، مربی‌ها (مهدی نادری/لیلا احمدی/امیر توکلی)، ۳ کلاس + پلن‌ها، اعضا، اشتراک‌ها، حضور، پرداخت/هزینه و تنظیمات مطابق دموی فعلی.
- `manage.py check` + migrate + runserver + تست مرورگری مسیرهای کلیدی (ورود → داشبورد → فیلتر اعضا → حذف با مودال → ثبت حضور → ثبت پرداخت → مالی → تنظیمات).
